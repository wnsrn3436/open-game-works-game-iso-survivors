status: proposed

## target

LocalizationCore

## kind

feature

## problem

`LocalizationCore` applies one font per language as the default font, and content code does not set a font on a UI text element. The only Korean text font of the font catalog is the variable `NotoSansKR[wght]`, and its default instance draws light strokes. Titles, buttons and numbers of a commercial game UI are set in a bold weight, and body text in a regular weight, so a game needs more than one weight of the same font. Iso Survivors needs heavy titles, buttons and HUD numbers to read as a commercial game over its dark backdrops and the field.

## proposal

- The `language` table gets font weight columns `font_weight_body` and `font_weight_heading` (int, OpenType `wght`, e.g. 400 and 800). `load_fonts` applies the font chain as the default font with `font_weight_body`, and defines a theme type variation per UI text element type (`HeadingLabel`, `HeadingButton`) that uses the same chain with `font_weight_heading` (Godot: `FontVariation` with `variation_opentype` `wght`, over each font of the chain)
- Content code picks the heading weight on an element only by that theme type variation name (`theme_type_variation`), so it still does not set a font on an element
- When a font of the chain has no `wght` axis, the weight is ignored for that font and an info log is written

## workaround

Content draws heavy text with an outline in the text color (`font_outline_color` = `font_color`, `outline_size` about 1/11 of the font size for labels and 1/13 for buttons) and a dark shadow outline as the rim (`resource/prefab/**`, `resource/scene/title/title.tscn`). Code that recolors text sets the outline color with it (`run_hud_panel.gd` health text, `common_terms_hint.gd`), and a button that turns disabled sets its outline to the disabled text color (`CommonButtonText.match_outline`).
