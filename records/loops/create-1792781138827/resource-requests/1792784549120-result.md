## notes

- Models: `## art direction` asks for low-poly, so all of them were made with `blender` from primitive shapes.
  - Each model is one mesh with one flat-colored material per palette color, plus emissive materials for the glowing parts: eyes, lantern flame, gems, the aura and the lightning. A grey vertex color adds top-down light and a little variation per face.
  - The run tints enemies by multiplying the instance color with the vertex color, so the vertex color is only a grey factor. Models that are not tinted (hero, props, pickups, weapons) show the material colors without that gradient.
  - There are no image textures. The first version embedded a painted atlas in the `.glb`, and the pre-commit Godot import extracted it to `resource/model/*_paint.png`, which are files without a resource row. I removed those files and rebuilt with vertex colors.
  - Every model is scaled to exactly its `spec` `bounds`. The pivot is at the bottom center, the model faces +Z, and transforms are applied.
  - The UVs are the default primitive UVs. Nothing reads them, because there is no texture.
  - None of the models is rigged, and the requests had no `rig` or `animation_3d` key. So the living characters (hero, enemies) are static meshes, and any motion comes from content code.
- Particles: `RunEffect` restarts only its root `GPUParticles3D`. So the multi-part effects (enemy_death bone chips, level_up glow, lightning_impact flash and sparks) use a sub-emitter that the root's particles trigger at start, not a separate child emitter.
- The effect life tween lasts 700 ms. I set level_up to a 0.7 s lifetime to fit it, not the 0.8 s in its description.
- bgm: both ace-step tracks ended with a fade and then silence (lobby from about 85 s, run from about 117 s). I cut each one before its fade (lobby at 83 s, run at 115.5 s) and crossfaded the last 3 s (lobby) or 2 s (run) into the start with equal-power curves, so the loop point runs on with no gap.
  - As a result, lobby is 80.0 s (spec `length=90000`) and run is 113.5 s (spec `length=120000`).
- sfx: these variants came out almost silent, with a peak below −49 dBFS, and were made again with different prompts: `sfx/ui_click` variant 2 (twice), `sfx/bolt_fire` variant 2 and `sfx/axe_throw` variant 2.
  - Some sounds ended under −18 LUFS after `finalize` because the true-peak limit stopped the gain first: `sfx/upgrade_buy` −26 LUFS, `sfx/enemy_die` variants 1 and 2 at −24.1 and −22.2 LUFS, `sfx/chest_open` and `sfx/refuse` at −20 LUFS.
- Content-side points I saw while checking. These files are outside my scope and I did not change them:
  - The font shows at its default light weight. The HUD numbers need a bold weight, which means a variation setting such as `FontVariation` weight on the UI side.
  - The run field is lit very darkly, so `texture/ground` shows only near the player's lantern light.
  - `run.open_result` opened the result panel under the pause popup that `run.pause` had opened, and the pause popup stayed on top.
